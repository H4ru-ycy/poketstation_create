# ポケステ ドット絵アニメ

PocketStation (SCPH-4000) で 32×32 白黒のドット絵アニメを再生し、4音の曲を鳴らすプログラムと、その作成ツール一式です。

## 中身

| パス | 内容 |
|---|---|
| `src/main.c` | 再生プログラム本体 (C言語) |
| `src/crt0.S` | スタートアップ (ARMアセンブラ)。先頭にアニメ情報テーブル |
| `src/sound.c` `src/sound.S` | 4音の矩形波サウンドエンジン (タイマ2 FIQ, 7808Hz) |
| `src/poc.h` | ポケステのレジスタと BIOS (SWI) の定義 |
| `src/poc.ld` | リンカスクリプト (0x02000180 から配置) |
| `tools/mkpoc.py` | ヘッダ・アイコンを付けて `.bin` `.mcs` `.mcr` を作る |
| `tools/pmus.py` | 曲データ (PMUS) の作成と、実機と同じ計算の参照シンセ |
| `tools/embed_player.py` | 変換ツールHTMLに再生プログラムを埋め込む |
| `converter/converter.src.html` | 画像→ドット絵変換・編集・作曲・プレビューツール (スマホ対応) |
| `prebuilt/` | ビルド済みファイル (サンプルアニメ入り、変換ツール) |
| `tests/` | ARMシミュレータによる動作テスト |

## ツールを使う (ブラウザ)

GitHub Pages で公開した変換ツールを、スマホやPCのブラウザで開くだけで使えます。

- ツール: `https://<ユーザー名>.github.io/<リポジトリ名>/`
- サンプル (弾むボール + きらきら星): `download/anime.mcr` `download/anime.mcs`

`main` ブランチに push すると、GitHub Actions がビルド・テストをしてから自動で公開し直します (`.github/workflows/pages.yml`)。

## ビルド (PC)

必要なもの: `clang` + `ld.lld` + `llvm-objcopy`、または `arm-none-eabi-gcc`、Python 3

```sh
make                          # サンプルアニメ+サンプル曲で build/anime.mcr などを作成
make FRAMES=anime.pda MUSIC=song.pmu   # 変換ツールで書き出したアニメと曲を使う
make NOMUSIC=1                # 曲なし
make TOOLCHAIN=gcc            # arm-none-eabi-gcc を使う
make converter                # build/dot-studio.html (変換ツール) を作成
python3 tests/test_player.py build/anime.bin   # シミュレータで動作確認
```

オプション: `TITLE="タイトル"`、`FILENAME=BISLPSP00000XXXX` (7文字目は必ず `P`)、`DELAY=4` (1コマの時間、30Hz単位)

## 実機・エミュレータへの入れ方

1. `anime.mcr` をエミュレータ (no$psx など) のメモリーカードとして読み込み、動作を確認する。
2. 実機は、MemcardRex などの管理ソフトとカードアダプタ (MemCARDuino、PS3用メモリーカードアダプタなど) で `anime.mcs` を書き込む。
3. ポケステの時計画面で左右ボタン → アイコンが出たら決定ボタンで起動。

## 操作

| ボタン | 動作 |
|---|---|
| 決定 (短押し) | 一時停止 / 再開 |
| 決定 (2秒長押し) | 時計画面に戻る |
| 右 / 左 | アニメを速く / 遅く (1コマ 1/30秒 ～ 1秒) |
| 上 | 白黒反転 |
| 下 | 再生中は曲を鳴らす / 止める、一時停止中は1コマ送り |

本体に挿したとき (Docked) は画面の向きを自動で180度回転します。
時計画面の音量設定に従います (「小」で 1/4、「消音」では最初は鳴らさず、下ボタンで鳴らせます)。

## しくみ

- ファイル全体が `0x02000000` に割り当てられます。
  - `000h` タイトル (SC / MCX0 / エントリポイント)
  - `080h` PS本体用アイコン
  - `100h` 実行アイコンリスト
  - `180h` プログラム本体
  - その後ろにフレームデータ
- フレームは 1コマ 128 バイトです。32行 × 32bit で、bit0 が左端、1 が黒です。LCD_VRAM と同じ並びです。
- タイマ0 (CPU 3.99MHz ÷ 512、260カウント) をポーリングして 30Hz を作っています。
- フラッシュは 8bit 読み出しができないため、定数はすべて 32bit 単位で扱っています。
- 音はタイマ2 (CPU ÷ 32、16カウント = 7808Hz) の FIQ で鳴らします。
  - BIOS の FIQ コールバック (SWI 01h) に `snd_fiq` を登録します。
  - 1サンプルごとに4つの矩形波を足して、DAC (bit6-15 の符号付き10bit) に書き込みます。
  - コールバックが使うのは、BIOSが保存する r0/r1/r12 と、FIQ専用の r8-r11 だけです。
- 曲は16分音符ごとのステップで進みます。ステップの90%弱の時点で、次の音につながらない音を切って、音の区切りを作っています。
- 仕様の出典は psx-spx の「Pocketstation」章です: https://psx-spx.consoledev.net/pocketstation/

## .pda 形式

| オフセット | サイズ | 内容 |
|---|---|---|
| `00h` | 4 | `"PDA1"` |
| `04h` | 4 | フレーム数 |
| `08h` | 4 | 1コマの時間 (30Hz単位) |
| `0Ch` | 4 | 予約 |
| `10h` | N×128 | フレームデータ |

## .pmu (PMUS) 形式

| オフセット | サイズ | 内容 |
|---|---|---|
| `00h` | 4 | `"PMUS"` |
| `04h` | 4 | バージョン (1) |
| `08h` | 4 | ステップ数 S (16分音符の数) |
| `0Ch` | 4 | 1ステップのサンプル数 (= 7808×60÷(BPM×4)) |
| `10h` | 4 | ゲート (ステップ先頭から音を切るまでのサンプル数) |
| `14h` | 12 | 予約 |
| `20h` | S×16 | 各ステップに4ワード (メロディ, ハモリ, 和音, ベース) |

各ワードの意味:

- `0`: 休符
- `FFFFFFFFh`: 前の音をのばす
- それ以外: bit0-15 が位相の増分 (周波数×65536÷7808)、bit16-23 がデューティ (32/64/128)、bit24-31 が音量 (0-127)

## テスト

`tests/test_player.py` は、自作のARMシミュレータで再生プログラムを動かして確かめます。

- 画面: コマ順、速さ変更、一時停止、反転、終了、本体に挿したときの回転
- 音:
  - FIQ の出力を `tools/pmus.py` の参照シンセと1サンプル単位で比べます。
  - 壊してはいけないレジスタが守られているか、1回あたりの命令数が予算内かを確かめます。
  - 時計画面の音量設定 (普通 / 小 / 消音) ごとの動きを確かめます。
- 変換ツールの試聴も同じ計算で音を作るので、ツールで聞いた音と実機の音は同じになります。

```sh
python3 tests/test_player.py build/anime.bin 0   # 第2引数: 0=普通 1=小 2=消音
```

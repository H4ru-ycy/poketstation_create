# ポケステ ドット絵アニメ

PocketStation (SCPH-4000) で 32×32 白黒のドット絵アニメを再生し、4音の曲を鳴らすプログラムと、その作成ツール一式です。

## 中身

| パス | 内容 |
|---|---|
| `src/main.c` | 再生プログラム本体 (C言語) |
| `src/chara.c` | キャラクターモード (表情・時計・日数・コマンドで曲) |
| `src/font.h` `converter/font.js` | 時計と日数の数字・文字 (`tools/genfont.py` で作成) |
| `converter/card.js` | メモリーカード (.mcr) の読み書き (セーブの追加・削除・取り出し) |
| `converter/chara.js` | キャラクターモードの動き (ツールのプレビュー用。`chara.c` と同じ手順) |
| `src/crt0.S` | スタートアップ (ARMアセンブラ)。先頭にアニメ情報テーブル |
| `src/sound.c` `src/sound.S` | 4音の矩形波サウンドエンジン (タイマ2 FIQ, 7808Hz) |
| `src/poc.h` | ポケステのレジスタと BIOS (SWI) の定義 |
| `src/poc.ld` | リンカスクリプト (0x02000180 から配置) |
| `tools/mkpoc.py` | ヘッダ・アイコンを付けて `.bin` `.mcs` `.mcr` を作る |
| `tools/pmus.py` | 曲データ (PMUS) の作成と、実機と同じ計算の参照シンセ |
| `tools/embed_player.py` | 変換ツールHTMLに再生プログラムを埋め込む |
| `converter/converter.src.html` | 画像→ドット絵変換・編集・作曲・プレビューツール (スマホ対応) |
| `converter/omr.js` | 楽譜の画像から音符を読み取る処理 (ビルド時に変換ツールへ埋め込み) |
| `prebuilt/` | ビルド済みファイル (サンプルアニメ入り、変換ツール) |
| `tests/` | ARMシミュレータによる動作テスト |

## ツールを使う (ブラウザ)

GitHub Pages で公開した変換ツールを、スマホやPCのブラウザで開くだけで使えます。

- ツール: `https://<ユーザー名>.github.io/<リポジトリ名>/`
- サンプル (弾むボール + きらきら星): `download/anime.mcr` `download/anime.mcs`

`main` ブランチに push すると、GitHub Actions がビルド・テストをしてから自動で公開し直します (`.github/workflows/pages.yml`)。

## ピアノロールの編集と保存 (作曲パネル)

「ピアノロールの操作」で編集のしかたを選びます。

| 操作 | できること |
|---|---|
| 置く・消す | マスをタップして音符を置く。同じ音符をもう一度タップすると消える (画面のスクロールもできる) |
| なぞって置く | 押したまま右へなぞった長さの音符を置く。音符の上から押すとのばせる |
| のばす・縮める | 音符を押したまま左右に動かして長さを変える。後ろの音符に重なった所だけ上書き |
| 動かす | 音符を押したまま動かして、高さとタイミングを変える |
| 消しゴム | タップ・なぞった音符を消す |

- パソコンのマウスでは、どの操作でも音符の右はしをドラッグして長さを変えられます。
- 「元に戻す」「やり直す」は、1回の操作 (なぞり・ドラッグ) ごとに戻せます。
- 「曲を再生」は最初から、「表示している所から再生」はピアノロールに表示している小節から鳴らします。
- 「曲を保存」で名前をつけてこの端末に保存・上書き保存できます。保存した曲は一覧から開けます。MIDI (.mid) と曲データ (.pmu) にも書き出せます。
- 編集中の曲は、何もしなくても下書きとしてこの端末に残ります。

## 範囲を切り出す (作曲パネル)

作曲パネルの「範囲を切り出す」で、曲の好きな範囲を選んで使えます。

- 範囲は「はじめ・おわり (小節と拍)」に数字で入れるか、「ピアノロールで範囲を選ぶ」を押してから始まりと終わりの拍をタップします。選んだ範囲はピアノロールに色で出ます。
- 「範囲を試聴」で、その範囲だけをくり返し鳴らします (ポケステと同じ音)。
- 「この範囲だけ残す」で、曲をその範囲だけにします (「元に戻す」で戻せます)。
- 「この端末に保存」で名前をつけてブラウザに保存し、あとで「作曲パネルで開く」で呼び出せます。
- 「MIDI (.mid)」(4トラック・テンポつき) か「曲データ (.pmu)」でファイルにも書き出せます。
- 小節の途中で終わる範囲は、曲の長さを小節単位に切り上げます (最後は休み)。

## キャラクターモード

アニメを流す代わりに、キャラクターの顔を表示して、ボタンで遊べるようにします。
変換ツールの「キャラクターモード」で「キャラクターモードで書き出す」をオンにすると使えます。

| 操作 (ボタンは変えられます) | 動き |
|---|---|
| 待機 | 日付と時計 (初期値) か、キャラクターの顔を表示。決めた秒数さわらないと表示が消え、決定で戻る (ほかのボタンでは戻らない) |
| ボタンを押す | 表情が変わり、しばらくすると待機の表示に戻る (顔のときは、ときどき、まばたき) |
| 決めたボタンをすばやく2回押す (初期値: 上) | 日付・曜日・時計を表示 |
| 決めたボタンを長押し (初期値: 決定) | 基準日からの日数を表示 (初期値は2026年1月22日。『超かぐや姫！』のNetflix配信開始日) |
| 決めた順にボタンを押す (初期値: ↑↑↓↓←→) | 作曲パネルの曲を最後まで1回鳴らし、自動で待機に戻る。途中で決定を押すと止まる |
| 日付と時計の表示中に決定を長押し | 日付と時刻を合わせる (▲▼で数字を変える・◀▶で年/月/日/時/分を選ぶ・決定で決める。BIOS の SWI 0Ch) |
| どれかを3秒押し続ける | ポケステの時計画面に戻る (時刻合わせの間は除く) |

- 表情・まばたき・時計や日数の背景には、コマ列の好きなコマを割り当てます。
- 曲の間の表示は「表情2枚を交互に」「1枚の画像」「アニメーション」から選べます。
  アニメーションは、最初のコマとコマ数を決め、曲に合わせて (16分・8分・4分・2分音符ごと) か、決めた時間ごとに次のコマへ進みます。
  GIFや連番の画像を「画像から変換」で足したあと「最後に「画像から変換」で足したコマをアニメにする」を押すと、そのコマがすぐ使えます。
- 「見本の顔を入れて試す」で、シンプルな顔のコマを足して、すぐに試せます。
- 「日数画面の背景を作る」で、「公開から」「日」の文字が入った背景のコマを作れます。
- ツールのプレビューでは、液晶の下のボタンで実機と同じ動きを試せます。時計はスマホの時刻を使います。
- 日付と時刻は、ポケステ本体の時計 (BIOS の SWI 0Dh / 0Eh) を使います。時計が合っていないと日数は「--」になります。
- PCで作るとき: `make FRAMES=anime.pda MUSIC=song.pmu CHARA=project.json`

設定は曲データの後ろに `PCHR` ブロック (32bitワード44個、version 3) として入ります。並びは `src/chara.c` の先頭にあります。

## メモリーカード (手持ちのカードに追加・バックアップ)

変換ツールの「メモリーカード」で、ポケステやメモリーカードの中身をまるごと吸い出した .mcr を開けます。

- 今あるセーブを残したまま、作った作品 (アニメ・キャラクターモード) を空きブロックに追加できます。同じファイル名のセーブがあれば置き換えます。
- カードの中のセーブを一覧で見て、1件ずつ .mcs に書き出したり、消したりできます。.mcs の追加もできます。
- 「カードを書き出す (.mcr)」で、日付つきのファイル名で保存します。
- バックアップ: カードを開いたときの元の内容と、書き出したときの内容を、この端末のブラウザ (IndexedDB) に自動で残します (20件まで)。「開く」で戻し、「ダウンロード」でファイルにできます。
- 開いているカードの内容 (追加・削除のあと) も自動で残るので、ツールを開き直すと続きから使えます。
- 書き込みはカード全体を書き換えるので、必ず元のカードのバックアップをファイルで取っておいてください。

## MIDIから読み込む

変換ツールの「MIDIから読み込み」で、スタンダードMIDIファイル (.mid / .midi) の好きな範囲を切り取って曲にします。

1. 「MIDIファイルを選ぶ」でファイルを選びます。曲全体の音符が横長の図で表示されます。
2. 図をタップするか「はじめ (小節・拍)」を入れて、切り取りの始まりを決めます。「長さ」は好きな小節数にでき、「曲の終わりまで」も選べます。
3. 「パートの割り当て」で、メロディ・ハモリ・和音・ベースにどのトラックのどの音 (いちばん高い音 / 2番目 / 3番目 / いちばん低い音) を使うかを選びます。読み込んだときに自動で割り当てます。
4. 「切り取った部分を試聴」で、ポケステと同じ音で確かめます。
5. 「作曲パネルに入れる」で曲にします。

ドラム (10チャンネル) は割り当ての自動選択から外します。途中でテンポが変わる曲は、1つのテンポ (変えられます) で鳴らします。

## 楽譜から読み取る

変換ツールの「楽譜から読み取り」で、五線譜の画像から音符を読み、4つのパートのドレミに分けます。

1. 「楽譜の画像を選ぶ」で画像を選びます。複数ページは曲の順に並べます (← → で並べ替え)。
2. テンポと拍子 (ふつうは「自動」) を決めて「読み取る」を押します。
3. 読み取った音符が画像の上に丸で表示されます。拍の数が合わない小節は黄色になるので、そこを確かめます。
4. パートごとのドレミを必要に応じて直し、「作曲パネルに入れる」で曲にします。始まりの小節も選べます。

パートの分け方:

| パート | 取り出す音 |
|---|---|
| メロディ | 上の段のいちばん高い音 |
| ハモリ | 上の段の2番目の音 |
| 和音 | 下の段の和音の上の音 (無いときは上の段の3番目の音) |
| ベース | 下の段のいちばん低い音 |

向いている画像: 楽譜アプリや楽譜サイトのスクリーンショット、印刷された楽譜をまっすぐ撮った写真。ト音記号とヘ音記号、調号、臨時記号、付点、タイ、8va/8vb を読めます。
苦手な画像: 手書き、斜めの写真、歌詞やコード名が五線に重なる譜面、連符、装飾音。
自動生成したピアノ譜で試したときの正解率は、音の高さとタイミングで9割前後です。読み取った結果は必ず耳で確かめて直してください。
著作権のある曲は、自分で楽しむ範囲で使ってください。

## ビルド (PC)

必要なもの: `clang` + `ld.lld` + `llvm-objcopy`、または `arm-none-eabi-gcc`、Python 3

```sh
make                          # サンプルアニメ+サンプル曲で build/anime.mcr などを作成
make FRAMES=anime.pda MUSIC=song.pmu   # 変換ツールで書き出したアニメと曲を使う
make NOMUSIC=1                # 曲なし
make TOOLCHAIN=gcc            # arm-none-eabi-gcc を使う
make converter                # build/dot-studio.html (変換ツール) を作成
python3 tests/test_player.py build/anime.bin   # シミュレータで動作確認
make test                     # アニメ再生・キャラクターモード・メモリーカードのテスト
```

オプション: `TITLE="タイトル"`、`FILENAME=BISLPSP00000XXXX` (7文字目は必ず `P`)、`DELAY=4` (1コマの時間、30Hz単位)

## 実機・エミュレータへの入れ方

1. `anime.mcr` をエミュレータ (no$psx など) のメモリーカードとして読み込み、動作を確認する。
2. 実機は、MemcardRex などの管理ソフトとカードアダプタ (MemCARDuino、PS3用メモリーカードアダプタなど) で `anime.mcs` を書き込む。
3. ポケステの時計画面で左右ボタン → アイコンが出たら決定ボタンで起動。

## 操作

| ボタン | 動作 |
|---|---|
| 決定 (短押し) | 一時停止 / 再開 |
| 決定 (2秒長押し) | 時計画面に戻る |
| 右 / 左 | アニメを速く / 遅く (1コマ 1/30秒 ～ 1秒) |
| 上 | 白黒反転 |
| 下 | 再生中は曲を鳴らす / 止める、一時停止中は1コマ送り |

本体に挿したとき (Docked) は画面の向きを自動で180度回転します。
時計画面の音量設定に従います (「小」で 1/4、「消音」では最初は鳴らさず、下ボタンで鳴らせます)。

## しくみ

- ファイル全体が `0x02000000` に割り当てられます。
  - `000h` タイトル (SC / MCX0 / エントリポイント)
  - `080h` PS本体用アイコン
  - `100h` 実行アイコンリスト
  - `180h` プログラム本体
  - その後ろにフレームデータ
- フレームは 1コマ 128 バイトです。32行 × 32bit で、bit0 が左端、1 が黒です。LCD_VRAM と同じ並びです。
- タイマ0 (CPU 3.99MHz ÷ 512、260カウント) をポーリングして 30Hz を作っています。
- フラッシュは 8bit 読み出しができないため、定数はすべて 32bit 単位で扱っています。
- 音はタイマ2 (CPU ÷ 32、16カウント = 7808Hz) の FIQ で鳴らします。
  - BIOS の FIQ コールバック (SWI 01h) に `snd_fiq` を登録します。
  - 1サンプルごとに4つの矩形波を足して、DAC (bit6-15 の符号付き10bit) に書き込みます。
  - コールバックが使うのは、BIOSが保存する r0/r1/r12 と、FIQ専用の r8-r11 だけです。
- 曲は16分音符ごとのステップで進みます。ステップの90%弱の時点で、次の音につながらない音を切って、音の区切りを作っています。
- 仕様の出典は psx-spx の「Pocketstation」章です: https://psx-spx.consoledev.net/pocketstation/

## 曲の長さ

曲の長さに決まった上限はなく、ポケステの容量 (15ブロック = 120KB) に入るところまで使えます。
1小節 (16分音符16個) は256バイトです。サンプルのアニメ (12コマ) と一緒なら約465小節まで入ります。
コマを増やすと、そのぶん入る小節数は減ります。作曲パネルの「長さ」の下に、今のコマ数で何小節まで入るかが出ます。

## .pda 形式

| オフセット | サイズ | 内容 |
|---|---|---|
| `00h` | 4 | `"PDA1"` |
| `04h` | 4 | フレーム数 |
| `08h` | 4 | 1コマの時間 (30Hz単位) |
| `0Ch` | 4 | 予約 |
| `10h` | N×128 | フレームデータ |

## .pmu (PMUS) 形式

| オフセット | サイズ | 内容 |
|---|---|---|
| `00h` | 4 | `"PMUS"` |
| `04h` | 4 | バージョン (1) |
| `08h` | 4 | ステップ数 S (16分音符の数) |
| `0Ch` | 4 | 1ステップのサンプル数 (= 7808×60÷(BPM×4)) |
| `10h` | 4 | ゲート (ステップ先頭から音を切るまでのサンプル数) |
| `14h` | 12 | 予約 |
| `20h` | S×16 | 各ステップに4ワード (メロディ, ハモリ, 和音, ベース) |

各ワードの意味:

- `0`: 休符
- `FFFFFFFFh`: 前の音をのばす
- それ以外: bit0-15 が位相の増分 (周波数×65536÷7808)、bit16-23 がデューティ (32/64/128)、bit24-31 が音量 (0-127)

## テスト

`tests/test_player.py` は、自作のARMシミュレータで再生プログラムを動かして確かめます。

- 画面: コマ順、速さ変更、一時停止、反転、終了、本体に挿したときの回転
- 音:
  - FIQ の出力を `tools/pmus.py` の参照シンセと1サンプル単位で比べます。
  - 壊してはいけないレジスタが守られているか、1回あたりの命令数が予算内かを確かめます。
  - 時計画面の音量設定 (普通 / 小 / 消音) ごとの動きを確かめます。
- 変換ツールの試聴も同じ計算で音を作るので、ツールで聞いた音と実機の音は同じになります。

```sh
python3 tests/test_player.py build/anime.bin 0   # 第2引数: 0=普通 1=小 2=消音
python3 tests/test_chara.py build/player.bin 0   # キャラクターモード
```

`tests/test_chara.py` はボタン操作の台本どおりに再生プログラムを動かし、次のことを確かめます。

- 表情・まばたき・時計・日数・コマンドで曲・決定で曲を止める・3秒で終了
- 曲を1回だけ鳴らして、最後まで鳴ったら待機に戻ること。音は参照シンセと1サンプル単位で比べる
- 同じ台本で `converter/chara.js` (ツールのプレビュー) を動かし、画面が1tickごとに実機と一致すること (Node.js が必要)
